# Tool notes

Practical setup notes for [agent-review](../SKILL.md) in Claude Code and Codex.

## Install options

Copy this skill (or clone the repository for a user install) into `~/.claude/skills/agent-review/` (local Claude Code user), `<repo>/.claude/skills/agent-review/` (Claude Code project), `~/.agents/skills/agent-review/` (Codex user), or `<repo>/.agents/skills/agent-review/` (Codex project). Cowork and Claude Code cloud sessions do not read your local `~/.claude/skills/`; use a synced account skill or a committed project skill in cloud sessions. Copying avoids nesting another repository in a project. Keep `SKILL.md` and `references/` together.

As shipped, Claude Code can invoke this skill automatically, and its `effort: high` overrides session effort while active. For work installs, we recommend `disable-model-invocation: true` and/or removing `effort` in local frontmatter, together with the instruction-file snippet in the README; invoke `/agent-review` for a full review. The loaded skill body uses context. In our codex-cli 0.156.1 checks, `when_to_use` and `effort` did not control selection or effort; Codex used session reasoning effort. For claude.ai or Skills API uploads, remove those two Claude Code fields from frontmatter.

## Independent reviewers

Checked on Claude Code **2.1.296** and codex-cli **0.156.1** in October 2026; recheck on your version, for example with the marker test in [SKILL.md](../SKILL.md). These notes describe context isolation, not a guarantee of filesystem access control.

- **Claude Code repository context:** A conversation started inside a repository, including `claude -p`, can receive a git snapshot with branch, status, and recent commits; subagents can receive it too. For a cold review, run outside the repository, set `includeGitInstructions: false`, or set `CLAUDE_CODE_DISABLE_GIT_INSTRUCTIONS=1`. `--safe-mode` is not documented to remove this snapshot.
- **Claude Code subagents:** Run each reviewer as its own headless `claude -p` session, or dispatch reviewer subagents from one: in `-p`, fork mode is off unless `CLAUDE_CODE_FORK_SUBAGENT=1`; an `Agent(fork)` deny rule enforces no forks. Named subagents stay ordinary subagents in `-p`, but for independent reviewers omit `name` and deny `SendMessage`: a named agent with that tool can see and message siblings even without teams. Avoid a reviewer definition with `memory`, which can prime it with past work. Agent teams are experimental and off by default. In an interactive session, avoid the `fork` type. General-purpose/custom subagents can receive the `CLAUDE.md` hierarchy. `omitClaudeMd: true` (v2.1.271+) skips user/project/local `CLAUDE.md` for a subagent, not an [agent-team teammate](https://code.claude.com/docs/en/agent-teams); it is ignored when that agent runs as the main session via `--agent`. Managed policy still applies except for managed subagents. Verify the setting where possible; record when subagent context cannot be inspected. With teams enabled, dispatch without a `name`, or pass `isolation` on the call; a named subagent otherwise becomes a teammate in the main working directory.
- **Claude Code clean sessions:** Prefer `claude --safe-mode`, which disables `CLAUDE.md`, skills, plugins, hooks, and other customizations; managed hooks and settings policy still apply. A fresh `CLAUDE_CONFIG_DIR` with `--setting-sources user` may need its own login and still applies managed settings and, on a claude.ai login, loads claude.ai connectors, so use it with a non-claude.ai login. In an interactive session, check `/context`, `/status`, and `/skills` for what loaded. `/tasks` and transcripts in `~/.claude/projects/…/subagents/` offer partial inspection, not an assembled-context dump.
- **Claude Code read isolation:** Use `permissions.deny` `Read` rules and `permissions.blockReadsOutsideWorkingDirectories` to restrict file tools. Bash deny rules cover matched commands, but arbitrary subprocesses can still read files; use a sandbox for enforced isolation. Test a forbidden read and record the result. See [permissions](https://code.claude.com/docs/en/permissions).
- **Codex:** In our 0.156.1 setup, `spawn_agent` inherited parent context unless given `fork_turns: "none"`; agents shared a filesystem. A fresh `codex exec` session outside a repo avoids repository history. `-c project_doc_max_bytes=0` omitted `AGENTS.md` in our test; the [config reference](https://learn.chatgpt.com/docs/config-file/config-reference) defines the byte limit but does not specify the effect of zero. For `skills.config`, that reference says _folder_ but [Build skills](https://learn.chatgpt.com/docs/build-skills) shows a `SKILL.md` file path; the file path worked and the folder path did not in our 0.156.1 test. Verify with `codex debug prompt-input` and `/skills`. `codex exec --ignore-user-config` alone does not disable skill discovery; `codex debug prompt-input` rejected that flag in our test. A separate `CODEX_HOME` drops its config, instructions, and stored login, but **still discovers `$HOME/.agents/skills`**; disable those skills by their `SKILL.md` file paths too, then verify, and provide authentication for the new home.
- For either tool, give reviewers only the artifact and primary sources; keep earlier drafts and reviews outside their workspace. Choose the model with Claude Code `--model` or subagent `model`, or Codex `-m`. Where the tool exposes reviewer context, confirm withheld content is absent (for example, `codex debug prompt-input` was offline and made no model call in our test); otherwise record the unavailable check. Check skill discovery separately. A separate directory is instructed isolation. Call it **enforced** only if an access-control boundary prevents reading withheld files, and test that boundary. Add `reviews/` to the reviewed project's `.gitignore`, or keep the review root outside the repository; this skill's shipped `.gitignore` covers only its own repository.
